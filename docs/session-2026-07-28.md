## 3. What broke, and what it taught

This is the useful section. Four of the five entries are cases where a CHECK was wrong, not
the code.

### The server was serving a build from before the edits

Port 3000 was held by `npm run start`, a production build predating the session. Nothing
hot-reloaded. The first "after" capture came back **byte-for-byte identical** to the baseline,
which is the only reason it was caught. **Every browser audit in the gate hardcodes
`localhost:3000`**, so the whole gate would have graded stale output and passed.

**Rule: before trusting any browser result, confirm what is actually serving port 3000.**
`npm run start` looks identical to `next dev` from the outside and never reloads.

### Three probes cried wolf

1. **"The end reveal is stuck invisible."** The probe measured mid-smooth-scroll. It works.
2. **"The slider drag is broken."** The element sat at y=1892 and the probe sent mouse events
   outside a 900px viewport. Dragging works and drives the maths live.
3. **"The radar chart is fine."** Rect maths found no overlap, because the defect was not an
   overlap: the block got *worse the wider the window went*.

**Rule: a probe that reports a failure is a claim about the probe as much as the page.
Reproduce it a second way before fixing anything.**

### An audit that could not see the defect

Beat 04's diagram rendered its labels between **3.6px and 9.4px** at every width. `audit:type`
could not see it: its query covers `p, li, code, pre, td, th, dt, span`, not SVG `<text>`, and
even had it looked, `getComputedStyle().fontSize` reports the **declared user unit** (13px),
never the rendered 4.7px. The audit read 13px and passed.

**Rule, and it is the same one as yesterday: text inside a viewBox scales with the box, and no
audit can see it. Labels go in HTML.** The maturity radar was built that way from the start.

### Wider window, worse layout

The maturity block's reason column went from 764px at viewport 1200 to **304px at 1240**, with
rows wrapping from one line to three. The ring's flanking labels cost ~200px of whatever column
the chart is in: affordable when the chart owns a row, ruinous when it shares one.

**Rule: if widening the window makes something worse, a rule is reading the viewport when it
means the box.** That is now two container queries on this page for exactly that bug.

### Auto margins plus containment equals zero

Capping the radar figure and centring it with `margin-inline: auto` collapsed the chart to
**zero width at all 23 swept widths**. Auto margins cancel a grid item's stretch, so its inline
size falls back to `fit-content`, and `fit-content` under `container-type: inline-size`
resolves to nothing, because containment is the promise that contents do not size the box.

**Rule: a container element must stay stretched. Cap and centre something INSIDE it.**

## 5. Standing debt

- **Beat 04's diagram is deleted, but its lesson is not enforced.** Nothing stops the next SVG
  from putting labels in a viewBox. `audit:type` still cannot see SVG text.
- **Beat 02 stacks below 1240.** Three across is desktop only, by arithmetic: three cells plus
  two chevrons need ~1164px before each clears 40 characters.
- **The gate explorer's chips are one column at 360/390.** "audit:structure" is 15 mono
  characters at 16px; two columns do not fit in 326px without breaking the floor.
- **Only Chromium.** No Safari or Firefox pass on the tablist, the range thumb's
  `::-moz-range-*` rules, or the SVG mock's font fallback.
- **No screen reader was run.** Roles and roving tabindex are correct by construction and axe
  passes, but nobody listened to it.
