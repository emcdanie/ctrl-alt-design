## 2. What shipped

### /design-system is now a case study of BELLA, on the real case template

The page stopped being a component showcase and became **an explorable explanation** on the
same shell, spine and beat template as the Drift and Code First cases:

```
CaseStudyLayout -> .layout-container -> CaseShellV2 -> six CaseBeats
```

Six beats, no bespoke sections, no page shell of its own. Verified: `/design-system` and
`/case-studies/brad-frost` both render **one** section left edge (132 at 1440, 32 below)
with text columns at 132/744. They read as the same product.

**Built:** `AgentDemo` (a switch that flips the same agent between guessing and grounded),
`ContractPipeline` (nudge a real token, the DTCG entry recomputes through the endpoint's own
function, a browser-computed contrast ratio is judged against AAA 7:1), the gate as content,
the maturity map with a you-are-here marker per axis.

**Deleted:** the six control specimen cards, the eight-orb identity grid, the leader
annotation UI as page furniture, `DesignSystemNav` and all its CSS, the COMING BEATS list,
`DesignSystemSpecimens.tsx` (678 lines), `ui/Select`, and `.beat--full`.

### The gate went from 15 to 16 audits

- **`audit:type` hardened.** It used to query `p, li, blockquote, dd` in cards and `p, li`
  sitewide with a 40-character threshold, so a `<code>` specimen at 14px and every table cell
  were structurally invisible. Now covers `code, pre, td, th, dt, span` at a 16-character
  threshold. **It caught 48 real failures**, all fixed or named as the metadata tier.
- **`audit:debt` added** (spec at specs/audit-debt/ (on spec/audit-debt)). Four checks: broken internal
  references, derived-list agreement, orphaned tokens, dead selectors in the audit scripts.
  It **earned its place on the first run**: five dead citations in docs, and 13 genuinely
  unused tokens left by the day's deletions, which were deleted rather than allowlisted.
- **The repo's first unit tests** (vitest, lib/bella/dtcg.test.ts (on spec/audit-debt)). `npm test` runs FIRST
  in the gate so a broken pure function fails in a second, not after two minutes of browser
  work. Tests are not an audit and do not change the derived count.

### Counts are derived, never typed

`lib/bella/gate.ts` derives the audit count from the gate script. It had been stale in four
places, saying thirteen while the gate ran fifteen. The page, the maturity rationale and the
status card now all read from one source. Going 15 to 16 required no edits anywhere.

## 3. What broke, and what it taught

**Read this section before writing any verification claim.**

### The gate carve-out incident

Beat 01 shows a deliberately off-brand "ungoverned agent output". It was first built as
**live rule-violating DOM** with a `[data-example]` carve-out added to three audits so the
gate would look away. That was wrong and it was reverted.

The fix that made the exemption unnecessary: **the bad example is now a flat `<img>` of a
static SVG.** A drawing has no colours, type sizes or contrast pairs for an audit to read, so
there is nothing to police and nothing to skip. The good side stays real live DOM that
passes for real.

**CLAUDE.md section 9 now bans per-element exemptions outright:** *an audit you can opt out
of is not an audit.* If something cannot pass, it does not get to be live DOM.

### Three times an automated check gave false confidence

1. **"No horizontal scroll" said the page was responsive. It was not.** The rail was
   `overflow-x: auto`, so it scrolled internally and the document never overflowed. Text ran
   edge to edge with zero gutter, which also does not overflow. **All three mobile bugs were
   invisible to that assertion by construction**, and it was still reported as ten green
   ticks.
2. **A focus-visibility check reported six failures that were not real.** It used
   programmatic `.focus()`, which does not trigger `:focus-visible`. Re-tested with real Tab
   presses: zero failures.
3. **A heading-obstruction check reported two failures that were not real.** It compared only
   vertical overlap; the rail at 1440 is a column beside the content, not over it. Re-tested
   with true 2D intersection: zero.

**The rule that came out of it:** an assertion that cannot fail is not a check. State the
failure condition for every check reported as passed, and **screenshot the target width
before claiming responsive**, every time.

### The root cause behind the mobile bugs

`CaseBeat` set vertical padding only and silently depended on an ancestor for the horizontal
gutter. Case routes supply one; the bespoke System page did not. **Fixed at the component:**
`.beat` now carries the container recipe itself and stands down inside `.layout-container` or
`.cs2` so the gutter is never doubled. Recorded as `requiresContext` in the component
contract, a field that did not exist.

The migration onto the real shell removes the cause rather than the symptom.
